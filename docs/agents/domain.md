# 领域文档

工程技能探索代码库时，应依据本项目的领域文档。

## 探索前阅读

- 根目录的 `CONTEXT.md`
- `docs/adr/` 中与当前工作区域相关的架构决策记录

如果这些文件不存在，应继续工作，不要主动提示缺失，也不要预先创建。领域建模工作应在术语或决策真正确定时按需创建它们。

## 文件布局

本项目采用单上下文布局：

```text
/
├── CONTEXT.md
├── docs/adr/
└── src/
```

## 领域术语

在问题标题、重构提案、假设和测试名称中，应使用 `CONTEXT.md` 定义的领域术语。不要擅自使用其明确避免的同义词。

如果所需概念尚未出现在术语表中，应重新确认项目实际使用的语言，或记录为领域建模待解决事项。

## 架构决策冲突

如果输出与已有 ADR 冲突，必须明确指出，而不是静默覆盖。例如：

> 与 ADR-0007 冲突，但鉴于……，建议重新审视该决策。
